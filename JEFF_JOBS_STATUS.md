## 2. Jobs framework, Test/Run Now, UI, Ask Jeff, templates — DONE
- Engine: `lib/jeff/jobs/{types,registry,detectors,schedule,coverage,store,runner,templates,interpret,tools,index}.ts`. Jobs are declarative (detector ids + sources + schedule + notification policy), never code. Detector registry: the 22 monitors wrapped, custom `client_scope_creep` (§87), specials `goal_trajectory`, `quiet_client`, `blind_spots`, `follow_through` (reserved stub for run B).
- TEST mode analyses current data and returns would-be findings; the only write is the `job_runs` row (no findings, alerts, push, missions). RUN / scheduled mode persists findings tagged `job_id/job_run_id`, auto-resolves only within the job, runs alerts under the job's policy (push floor, briefing-only, `max_per_day`: the newest overflow becomes informational). Partial provider outage: detectors needing that source are skipped, the run is marked `partial` with plain-language coverage notes, nothing is concluded from missing data.
- Schedules in the owner timezone (DST-safe): continuous / hourly / daily / weekly / monthly / custom cron / event-driven (+ daily safety tick) / manual. `/api/cron/jobs` every 15 min (`vercel.json`); event-driven jobs also fire after webhook syncs for their provider.
- Job-scoped rules: `operating_rules.target_job`; the global monitor run ignores them, the job runner applies global + its own.
- APIs (owner + aal2, Zod, audited `job_created/updated/paused/resumed/deleted/run/test`): `GET/POST /api/jobs`, `GET/PATCH/DELETE /api/jobs/[slug]` (DELETE non-system only), `POST …/test`, `POST …/run`, `GET …/runs`, `GET …/findings`, `POST /api/jobs/interpret`, `GET /api/jobs/templates`, `POST /api/jobs/blind-spot-scan` (202 + `scanId`), `GET/PATCH /api/jobs/runs/[id]` (poll progress; feedback on test results). Feedback route accepts `already_knew` (acknowledge quietly + propose a narrow rule) and stamps `job_id`.
- UI: nav "Jeff's Jobs" (briefcase); `/jobs` roster (source dots connected/missing, schedule, last run, findings this month, status pill, Test · Run now · Open); `/jobs/[slug]` (Overview, Purpose, Sources, Schedule, Notification policy, Rules for this job via `RuleEditor targetJob`, Last run, Run history, Findings with feedback incl. **Already knew this**, Settings; Test / Run now / Pause / Resume / Edit / Disable / Delete); + Add Job modal (describe in plain language → proposal → create or draft; browse templates; configure manually); TEST MODE panel (Useful / Wrong / Too noisy / Ignore pattern / Create rule).
- Ask Jeff tools: `list_jobs`, `get_job`, `run_job` (test|run), `pause_job`, `resume_job`, `create_job_from_description`, `update_job_policy`; system-prompt guidance added.
- NL → `JobDefinitionInterpretation`: deterministic intents first (§87 sentence → weekly Fri 07:05, portal + Stripe, `client_scope_creep`; "Every week, look for something important I might be missing" → the system Blind Spot Scanner), strict-schema Claude fallback with hard guards (detectors must exist, sources must be connected, never `safe` unless the deterministic parse agrees). `jobs_auto_create_safe` decides active vs draft.
